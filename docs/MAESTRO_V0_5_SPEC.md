# MAESTRO v0.5 — ADAPTIVE MAESTRO

## Objective

Connect the Learning Plane and Academy to the real runtime through governed, reversible policies.

## Adaptive domains

### EX Routing
Learns which Councils are normally needed for verified mission families.

### Council Context
Learns context budgets and inclusion strategies while preserving mandatory constitutional context.

### Tool Selection
Learns which permitted tool performs best for a Council/task family/capability.

### Model Selection
Learns which provider-neutral model satisfies the required quality/risk envelope at the best measured operational tradeoff.

### Retry Strategy
Learns which remediation strategy historically resolves a failure family while avoiding repeated failed strategies.

### Skills
Distills repeated successful workflows into reusable skill candidates.

### Archetypes
Discovers recurring structural mission forms from verified experiences.

## Activation pipeline

```text
EXPERIENCE
→ LEARNING
→ CANDIDATE POLICY vN+1
→ ACADEMY
→ HISTORICAL REPLAY
→ SHADOW TOURNAMENT
→ ADAPTIVE CONTROLLER
→ PROMOTION EVIDENCE
→ AY VALIDATION
→ EX AUTHORIZATION
→ ACTIVE
```

## Rollback

```text
ACTIVE vN+1
→ runtime regression / governance decision
→ AY acknowledgement
→ EX rollback authorization
→ ACTIVE vN
```

No active policy is overwritten.

## Non-negotiable separation

Adaptive routing cannot redefine Council authority.

Adaptive tool selection cannot bypass Tool Registry.

Adaptive model selection cannot bypass Council/model capability requirements.

Adaptive context cannot hide binding constraints.

Adaptive retries cannot bypass OP.

Academy cannot activate its tournament winner.
